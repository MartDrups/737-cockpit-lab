# 737 Cockpit Lab — копия для GitHub Pages

Самостоятельная копия действующего 737 Cockpit Lab. Основной сайт продолжает работать на https://737cockpitlab.pages.dev и не связан с публикациями из этого репозитория.

Исходник этой копии — сохранённая опубликованная сборка Cloudflare от 20.10.2026, версия 27. Код приложения соответствует коммиту `a10ed1c5ac4d406df480be4e0d82794782e47a4a`, основной репозиторий — `b3acd27df4133c2bf36821f9c22833a2ab33d31c`.

## Содержимое

- `public/` — полный сайт с учебными материалами, графикой и озвучкой.
- `PUBLIC_SHA256SUMS` — контрольные суммы файлов поставки.
- `scripts/prepare-github-pages.py` — воспроизводимая подготовка отдельной копии из оригинальной сборки.
- `.github/workflows/pages.yml` — проверка файлов и публикация только на GitHub Pages.

Каталог содержит 632 записи CBT, из них 631 доступна, и 27 нормальных процедур. Содержимое уроков, процедуры, тексты систем и код интерфейса перенесены без изменений. На сервере часть ресурсов хранится в `.gz`; браузерный service worker восстанавливает исходные URL, содержимое и MIME-типы. Публиковать нужно весь каталог `public/`, включая `.gz`, без дополнительной распаковки или сжатия.

Копия подготовлена для нового репозитория `737-cockpit-lab` и пути `/737-cockpit-lab/`. Изменены только адреса страницы обновления, совместимость загрузки плееров со статическим хостингом и связанные контрольные суммы офлайн-режима. Добавлены переходы для адресов плееров без `.html` и маркер `.nojekyll`. Файл `_headers` исключён: он предназначен для Cloudflare.

## Публикация

В настройках нового репозитория открыть **Settings → Pages → Source → GitHub Actions**. Workflow запускается после изменения поставки в `main` или вручную через **Actions → Publish 737 Cockpit Lab copy → Run workflow**. Он не имеет доступа к Cloudflare и не может обновлять основной сайт.

После публикации проверить работу приложения, уроков и офлайн-режима в Chromium и WebKit, затем доступность нового адреса из российских сетей.

История прохождения и скачанные офлайн-материалы привязаны к адресу сайта. На новом адресе они создаются отдельно; сохранённые данные основного сайта остаются на прежнем адресе.
